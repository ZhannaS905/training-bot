# Training Test: активация и уведомления

Репозиторий ZhannaS905/training-bot, существующая ветка
`delivery/training-test-repair-20261027`. Только Training Test
`bot_1792646494_1197_zhanna`, Firebase `fitpp-test`, synthetic-v1.

## Активация

Личный `/start` → «📱 Поделиться номером телефона» → подписанный собственный
контакт → единственная действующая карточка demo-client-1…4 с этим телефоном →
транзакционная привязка. Имя в контакте не является подтверждением привязки.
MAX user_id и личный chat_id берутся из аутентифицированного события, не вводятся
вручную. Подпись HMAC, max_info.user_id, окно 5 минут, отсутствие пересылки,
единственный TEL и нормализация 8/7 сохраняются.

Участники не ограничены TEST_ADMIN_IDS. Административные команды по-прежнему
ограничены этим списком. Чужие clientId/user_id/chat_id не перезаписываются.
Одна карточка, MAX ID и личный диалог могут участвовать только в одной привязке.

При успешной активации бот сохраняет notificationsEnabled:true и
recoverNotifications:true. Повторное подтверждение собственного контакта
включает эти флаги у прежней выключенной привязки; затем повтор идемпотентен.
Простое /start не меняет привязку и не включает отправку.

Область записи остаётся одним документом:
fitppTestWorkspaces/synthetic-v1/notificationBindings/training-test.
Основной документ states/main только читается, карточки и деньги не меняются.

## Уведомления и восстановление

Посещение/сгоревшее занятие (включая предупреждения о последнем/нулевом
остатке), покупка, продление, заморозка и истечение срока работают для каждой
включённой тестовой карточки. Перед отправкой проверяются /me, личный диалог и
его фактический пользователь против защищённой привязки. Общие TEST_ALLOW_*
разрешения не расширяются.

После подтверждения контакта watcher один раз проверяет сохранённую историю
этого участника, перечитывает состояние перед каждым сообщением и отправляет
непредпринимавшиеся ранее сообщения. Используются прежние устойчивые ключи
покупок/продлений/заморозок, посещений и срока. Предыдущие claims, в том числе
старые attempted с неизвестным результатом и неоднозначные сетевые ошибки,
не удаляются и не повторяются. Завершение восстановления также фиксируется в
существующем журнале /app/data/fitpp-notification-attempts-v1 и переживает рестарт.
Работает единственный watcher под прежней блокировкой supervisor.

Восстанавливаются только события с доказательством в текущем тестовом состоянии:
mutationReceipts с действующим циклом абонемента, подтверждённые visitOps/visits
с действующим абонементом, просроченный действующий абонемент с остатком.
Удалённые, отменённые, неоднозначные события и неизвестные результаты прошлых
отправок не реконструируются. В старом посещении выводится текущий остаток
с подписью «Сейчас», а не выдуманный остаток на дату исторического списания.
Восстановление не выполняет повторных покупок, списаний или изменений Firebase.
Сообщения помечаются «Пропущенное уведомление».

## Что требуется для применения

На момент проверки опубликованные Rules разрешают лишь создание одной
привязки demo-client-1 и запрещают update; текущий реестр содержит только её.
Поэтому одно обновление Bothost не решает сохранение второго участника.

Подготовлены:
- CONTACT-LINKING.firestore.rules — замена только блока реестра;
- CONTACT-LINKING.full-proposed.rules — полный кандидат на основе прочитанных
  действующих Rules (7522 символа до изменения), остальные блоки сохранены;
- test-rules/contact-linking.cjs — проверки полного кандидата в локальном
  Firestore emulator, проект demo-fitpp-notifications, порт 8857.

Новые Rules дают get/create/update только существующему maxTestOwner(), только
реестру этого тестового бота, максимум четырём тестовым карточкам. Уникальность
карточки/MAX ID/диалога проверяется попарно; старые идентификаторы неизменяемы,
удаление и перестановка строк запрещены. Разрешено добавлять максимум одну
строку или включать флаги уведомлений существующей. List/delete запрещены.
Опубликованную версию нужно повторно сверить перед заменой. Не публиковать
этот полный файл поверх более свежих изменений других разделов.

Публикация Rules и обновление/перезапуск Bothost выполняются только с отдельного
разрешения пользователя либо самим пользователем. Код и локальные проверки
не подтверждают фактическую доставку сообщений.

После применения правил и сборки из той же ветки второй участник повторяет
/start и делится своим номером. Номер должен совпадать с карточкой FitPP.
После ответа «Привязка сохранена…» watcher проверяет восстановление на ближайшем
цикле (обычно до 30 секунд, плюс время отправки). Ранее активированный участник
с выключенными уведомлениями также повторяет подтверждение контакта.

Сохранить настройки CONTACT_LINK_ENABLED/REPLY_ENABLED/WRITES_ENABLED=true,
OWNER_DIALOG_ENABLED=false, BOT_MODE=test, FIREBASE_PROJECT_ID=fitpp-test,
FITPP_NOTIFICATION_SUPERVISED=true, FITPP_NOTIFICATION_RECEIPTS_ENABLED=true,
FITPP_NOTIFICATION_EXPIRY_ENABLED=true и прежние credentials/volume/CHAT_IDS.
AUTO_PUBLISH, TEST_ALLOW_SEND/EDIT/DELETE остаются false. CMD по-прежнему
training-test-supervisor.cjs; бронирования и автопостинг продолжают работу.
