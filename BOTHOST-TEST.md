# Training Test: безопасный профиль BotHost

Подготовлено только для `refactor/cleanup-training-bot`. Развёртывание, изменение
подписок MAX и включение обработки реальных событий пока не разрешены.
Обычные `bot.js`, `config.js`, `test-launch.cjs` и локальный порт 18081 этот
профиль не меняет. Ускоренный тест и его часы сюда не подключаются.

## Поля нового тестового экземпляра BotHost

| Поле | Значение |
|---|---|
| Платформа | MAX |
| Язык | Node.js 22 или новее |
| Репозиторий | https://github.com/ZhannaS905/training-bot.git |
| Ветка | refactor/cleanup-training-bot |
| Главный файл | bothost-test.cjs |
| Использовать домен | Включено |
| Порт | 3000 |
| Кастомный домен | Пустой, автоматический HTTPS BotHost |

Справочник переменных — `bothost-test.env.example`. Этот файл не загружается
автоматически; действительные значения задаются только в секретных настройках
НОВОГО тестового экземпляра. Существующий BotHost не редактировать.

Обязательны `BOT_MODE=test`, `CHAT_IDS=-80345864298680`,
`WEBHOOK_SECRET` (прежний), `TEST_EXPECTED_BOT_ID` (подтверждённый числовой ID)
и `TEST_EXPECTED_STATE_SHA256` (SHA-256 согласованного файла state.json).
`PORT=3000`, `HOST=0.0.0.0`, `STATE_DIR=/app/data/training-test/live` закреплены
профилем: другие значения приводят к отказу.
`ADMIN_IDS` можно оставить пустым: административные команды в этом профиле
отключены. Личные ID администраторов в репозиторий не включаются.

Токен задаётся в `TEST_BOT_TOKEN`. Допускается автоматически переданный BotHost
`BOT_TOKEN`, если это единственный токен либо он точно равен `TEST_BOT_TOKEN`.
Конфликт токенов запрещён. Никакой токен не считается тестовым до GET `/me`:
проверяются числовой ID, username `id623401053090_1_bot`, тип и значение `is_bot`.
Затем GET проверяет тестовый чат и членство именно этого бота. Ошибка MAX,
авторизации или структуры ответа запрещает открытие слушателя и хранилища.

## Приёмочный режим без изменений MAX и голосований

`AUTO_PUBLISH`, `TEST_ALLOW_SEND`, `TEST_ALLOW_EDIT`, `TEST_ALLOW_DELETE` должны
отсутствовать либо иметь строковое значение `false`. Значение `true` отвергается:
эта версия не содержит переключателя, разрешающего изменения без следующей
согласованной доработки. API-фасад не предоставляет общий request и запрещает
send/edit/remove до сетевого запроса. Транспорт дополнительно разрешает только
фиксированные GET-маршруты MAX. Подписки не создаются и не удаляются.

Планировщик, публикация, drain сохранённых событий и refresh опросов не
запускаются. Просроченные published/deleting и dirty-записи сохраняются без
изменений. Включение публикации, удаления или обработки голосов — отдельный этап.

После разрешённого развёртывания приёмочные проверки:

- GET `/health` — 200 только после проверки личности и открытия ожидаемого
  хранилища; ответ содержит только ready/mode.
- GET `/webhook` — 404.
- POST `/webhook` без правильного secret — 403.
- POST с прежним secret и заведомо некорректным JSON `{` — 400, без события.
- Реальный JSON события с правильным secret — 503, включая чужие группы.
  Событие не записывается, не обрабатывается и не подтверждается ложным 200.

Существующий webhook нельзя переключать на этот приёмочный профиль: обработка
реальных событий пока намеренно закрыта. После отдельного разрешения потребуется
подготовить обработку событий и только затем согласовать переключение подписки.

## Постоянные данные

Использовать отдельное постоянное хранилище нового тестового экземпляра:

- `/app/data/training-test/live/state.json` — согласованная копия обычного
  тестового состояния с прежним удалённым опросом, голосом, именем и историей.
- `/app/data/training-test/archive/accelerated-cleanup/` — отдельная резервная
  копия результата ускоренного теста. Не заменять ею обычное состояние.
- `/app/data/training-test/backups/` — резервные копии вне live.

Переносить данные только из остановленного источника, без `.lock` и временных
файлов. Не включать их в Git. Никакой миграции этот запуск не выполняет.

В `TEST_EXPECTED_STATE_SHA256` внести SHA-256 исходного согласованного state.json;
проверить такой же SHA-256 после копирования. Хеш не содержит токенов и не
раскрывает содержимое голосования. Профиль не создаёт отсутствующее хранилище:
отказ при отсутствии файла, несовпадении хеша, пустой истории/опросах, событиях
в inbox, чужом чате, символьных/жёстких ссылках или повреждённой структуре.

После проверки берётся обычная эксклюзивная `.lock`, затем содержимое проверяется
повторно. Вторая копия не может открыть тот же каталог. При штатном завершении
SIGTERM/SIGINT снимается только собственная блокировка, state.json не меняется.
После аварии блокировку автоматически не удалять; требуется отдельная сверка
отсутствия процесса. Запускать один экземпляр, без перекрывающихся обновлений.

До реальной эксплуатации после разрешённого развёртывания проверить сохранность
хеша файла при рестарте и обновлении BotHost. В приёмочном режиме состояние
не меняется, поэтому тот же ожидаемый SHA-256 подходит для повторных запусков.
При будущем разрешении записи потребуется отдельная политика контрольных точек.

## TLS и окружение

В Git добавлен только публичный CA `certs/russian-trusted-root-ca.pem`, без
закрытого ключа. Проверяются закреплённый SHA-256-отпечаток, срок, CA и самоподпись.
Токены, webhook secret, подтверждённый числовой ID бота и содержимое состояния
в код не записываются.

`bothost-test.cjs` запускает чистый дочерний процесс с
`NODE_TLS_REJECT_UNAUTHORIZED=1` и абсолютным `NODE_EXTRA_CA_CERTS`, установленным
ДО запуска Node. На BotHost с корнем `/app` это
`/app/certs/russian-trusted-root-ca.pem`. Системные доверенные CA сохраняются.
Посторонние переменные, BOT_TOKEN-алиасы и preload-настройки дочерний процесс
не наследует. `NODE_OPTIONS` и неожиданный путь дополнительного CA запрещены.
Секреты передаются только окружением, не аргументами и не файлами; ошибки запуска
выводятся без сырых ответов MAX, заголовков и значений переменных.

## Офлайн-тесты

`node --test test/bothost.test.js` — заглушки MAX, временные каталоги, случайный
loopback-порт для проверки HTTP. Реальные токены и данные не используются.
`node --test test/*.test.js` — общий набор локальных тестов.
