## Что установлено

settings(env) корректно возвращает uid из FIREBASE_BOT_UID. Изменение UID не требуется.
Успешный auth-read проверяет только states/main; полный prepare дополнительно

SDK с форматом снимков клиентского SDK, openedAt из запроса и revision 84.

Исходная причина DIRECT_READ_PREFLIGHT_REJECTED и DIRECT_STARTUP_REJECTED
не установлена без результата диагностики в реальной среде. Не менялись правила,
схема данных, идентичность, scope, подпись или защитные флаги ради обхода отказа.

## Изменения

Preflight выводит фиксированный префикс отказа и stage/reason из закрытых списков.
Примеры: stage=READ_MAIN reason=permission-denied,
stage=POLL_VIEW reason=POLL_VIEW_METADATA, stage=BRIDGE_SETTINGS reason=INVALID_JSON.
Неизвестные ошибки дают UNKNOWN. Сообщения SDK, stack, UID, токены, адреса,
содержимое документов и параметры среды не выводятся. Внешний код завершения 1
сохранён. Упаковочный тест обновлён для нового формата.

Подтверждён отдельный дефект: prepare проверял закрытие только до подключения.
При закрытии во время login/transaction он мог вернуть успех. Добавлены проверки
после подключения и чтения с закрытием сессии при отказе. Новый тест на исходном
runtime падает с Missing expected rejection; на исправленном проходит для обоих
сценариев. Срок остался 26 октября 2026, 21:00 МСК.
